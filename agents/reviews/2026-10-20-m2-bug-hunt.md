## 2. Attack checklist

Run every item against **fresh release builds of `origin/main`**. Use your own CAIM instance, isolated with its own `CRAFT_AI_ENDPOINT` and `CRAFT_AI_MODELS` copies, so Erik's live manager is never touched. For each item record: the command or steps, expected vs actual, and the log path. A pass is one line; a failure gets a minimal repro.

**A. Old and new peers (protocol).**
1. M2 PhotoCraft against an M1-era CAIM (tag or commit before MG-10). Generative Fill works; an AI Select Subject gives the exact "isn't installed / Open Craft AI Manager" sentence, with no crash and no hang.
2. An M1-era PhotoCraft build against M2 CAIM. Generative Fill still works, and the extra result fields are ignored.
3. `/v1/tasks` with one model missing: that task is listed `ready:false`, and PhotoCraft refuses before encoding anything.

**B. Cancel and error paths.**
1. Cancel during a mask job, during model load, and during a queued job: each ends `cancelled`, leaves no stale message and keeps no input in memory (C3/C4 regressions).
2. Kill CAIM mid-job. Then restart CAIM, so it has a new token, while PhotoCraft is open. Expect the plain sentences, with no "lost the connection" for a 401 (X2 regression).
3. CUDA folder missing, one provider DLL missing, or `CRAFT_AI_CUDA` pointing at an empty folder: the result says `cpu` with the right `fallback_reason`, and `activity.jsonl` agrees.

**C. Limits.**
1. Subject mask (Select Subject and Remove Background, `method: "ai"`) on a 20000×20000 canvas: the image is **downscaled** to the task's `max_pixels` before anything is encoded, and the mask comes back and is scaled up (amendment 18). A refusal because of the document's size is a **DIFF**. Generative Fill on a selection that large may refuse, but only before reading pixels. Measure peak RAM for both.
2. Inputs of 1×1, 1×200000 and 200000×1; an empty selection; a 1-pixel selection.
3. Document modes. **16-bit and 32-bit RGB must work** for all three AI commands (32-bit clamped, with the note in the result): a refusal there is a DIFF. Grayscale, CMYK and indexed are not supported yet and must refuse with a plain sentence. A layer with transparency, a hidden layer and a layer in a group must work. With an adjustment layer selected, the command either works or refuses with a sentence. Nothing panics.
4. Remove Background with `method: "ai"` on a layer that already has a mask: undo restores the exact old state in one step.

**D. Downloads and resume (MG-12).**
1. Kill `caim models install` at about 30%, then resume: it resumes, re-hashes, and ends up verified.
2. A corrupted `.part` (flip bytes), a `.part.json` naming a different size or SHA, a truncated `.part.json`: each is refused or restarted cleanly, and never marked verified.
3. Two `caim models install birefnet` at once, and an install while a manager is serving.
4. `caim cuda install --accept-note` interrupted, then re-run.

**E. `caim open` and `app.json`.**
1. Two `caim open` at the same moment: exactly one manager starts.
2. A stale `endpoint.json` whose port is now served by **something else** (`python -m http.server` on that port answering 200 to everything): `caim open` must not treat it as CAIM, and PhotoCraft must not send it the image or the token.
3. `app.json` that is malformed, has a relative path, names `notcaim.exe`, names a directory called `caim.exe`, names a path with spaces or non-ASCII characters, or is version 2. Expect: no button, or a refusal sentence, and never a launch of the wrong program.
4. PC-10's click: CAIM not running plus a valid `app.json` means one click starts it, and a second click while it's starting doesn't start a second one.

**F. Security rules.**
1. `netstat -ano`: CAIM listens on 127.0.0.1 only.
2. A request with the wrong `Host` header, without the token, or with a wrong token: refused, and with the C1 slow-header fix (head deadline) still holding.
3. Search `activity.jsonl`, CAIM's console output, PhotoCraft's log, every receipt written by this task and the `%LOCALAPPDATA%\CraftAI` folder for the token string: **zero hits**. Search without ever printing the token: count or list file names only (`Select-String -SimpleMatch -List ... | Select-Object Path` or `rg -l -F`), never the matching lines, and record only paths and hit counts.
4. Endpoint file permissions on Windows (BF-04): another local user can't read it. Use `icacls` and record the output.
5. PC-11: a PSD with a crafted or garbage `pcai` block (truncated, huge length, invalid UTF-8, nested) opens without a panic and without showing junk as provenance. Fuzz it 1,000 times if a fuzz target exists, otherwise use 20 hand-made files.
6. No pickle and no `.pt`/`.bin` checkpoint loading anywhere in CAIM: `rg -n "pickle|torch.load|\.pt\b|\.ckpt|\.bin\b"` in both repos, with the hits explained.

**G. Do the guards test what they claim?** For each line in both repos' `agents/guards.txt` that protects M2 work (PC-08, PC-09, PC-10, PC-11, BF-04, and CAIM's MG-10/11/12 lines), make **one deliberate one-line break** in the code it protects, in a scratch worktree that never gets pushed. The break must **compile** and must violate the behaviour the guard claims to protect (a syntax or type error proves nothing). Confirm that guard goes red, name the specific test that failed, then undo the break. Report every guard that stays green.

**H. GPU (Codex-cloud on the desktop app, Strata stopped, like MG-11b).**
1. 50 fills and 50 subject masks back to back on the card. Record VRAM and RAM at 0/10/50: no steady growth.
2. Start Strata mid-session so the card fills up. The next job falls back with `insufficient_memory`, and it moves back to the card once Strata stops.
3. `--device cuda` against Auto, and what `activity.jsonl` records for each.

Severity scale (M1's, with security split by how hard it is to exploit; Claude, Oct 20):
- **P0:** a crash or data loss, or a security hole anyone can use on a normal single-user install.
- **P1:** wrong output or a broken flow, or a security hole that needs a precondition (another logged-in user, a crashed manager, a relocated file).
- **P2:** bad UX or robustness, or security hardening (defence in depth against something that already needs the user's own rights or an unusual setup).
- **P3:** a nit.

P0 and P1 are fixed before PC-12; P2s are fixed unless Erik defers one in writing (SPEC 20).

**Checked and correct (BH-02c, by reading):**
- **PC-10 launch:** the registration is re-read and re-checked at click time; it's started by absolute path with the single argument `open`, with no shell, no PATH lookup, no window and null stdio; the reaper thread collects the child; the read is capped at 64 KiB and `stat` is checked before `open`, so a FIFO can't block the UI; the name check is case-insensitive on Windows only.
- **MG-12:** `app.json` and `endpoint.json` are written to a temp file and renamed into place; the endpoint is removed only if it still holds this run's token; `open.lock` is an OS lock that is never unlinked (no stale window, no inode race); a 200 or 503 from a stranger doesn't count as a running manager in `caim open`. Resume: `.part.json` must match the catalog's URL, revision, SHA-256 and size; a server that ignores `Range`, or answers 416, is handled; the whole file is hashed against the pinned SHA-256 before it is marked verified.
