### `crates/ai-client/src/endpoint.rs`

- `read_file` now judges **the handle it opened** (`file.metadata()`, not `std::fs::metadata(path)`), which is upstream's pattern: nothing can be swapped in between the check and the read.
- `!meta.is_file()` -> `AiError::NoProvider`, the same answer as for every other unusable file, so a folder, a fifo, a device or a symlink to something odd still reads to the user as "Craft AI Manager isn't running".
- `#[cfg(unix)]` with `std::os::unix::fs::MetadataExt`: `meta.mode() & 0o077 != 0` -> `AiError::Other` with one sentence: `Craft AI Manager's endpoint file can be read or changed by other users (mode <octal>), so PhotoCraft won't use it. Restart Craft AI Manager to write a fresh one.` The octal is the low nine bits, so the user sees `644` rather than `100644`.
- Windows is left as it was, with a comment saying why: the file lives in this user's own `%LOCALAPPDATA%`, where those mode bits say nothing about who can read it. `#[cfg(unix)]` keeps the check out of the Windows build entirely.
- The `load` doc comment gained one paragraph, so the rule is visible where the function is described.

## Known gaps and follow-ups

- **Windows is deliberately unchanged** (prompt step 3). If Erik wants a Windows-side rule, the honest equivalent is an ACL check on `%LOCALAPPDATA%`, which is a different mechanism and a different task.
- The check is `0o077` (group or other **read or write**), matching upstream. A file the owner made `0640` with a group is refused too, which is the safe reading of "group or others can read".
- A symlink at the path is followed by `File::open` and judged by the target's metadata, so a symlink to a `0600` regular file still works; a symlink to a world-readable file is refused. That is upstream's behaviour too, and it is the check on the open handle rather than on the name that makes it race-free.
- PC-09 (Codex-cloud) also edits `crates/ai-client/src/tests.rs`: whichever merges second keeps both sides. The BF-04 change there is four lines inside `TempEndpoint::set`.
