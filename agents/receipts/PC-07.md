`agents/tools/run-guards.ps1`:

- **Parameters:** `-Repo photocraft|craft-ai-manager|both` (default `both`), `-Work E:\CraftML\work`
  (the folder that holds the two clones), `-RepoPath <dir>` to point one repo at another checkout (pass
  `-Repo` with it unless the folder is named after the repo), `-Only <ID>` to run one line.
- **Which checkout:** the script asks git which checkout it is sitting in (`rev-parse
  --show-toplevel` from `$PSScriptRoot`, then the `origin` URL to name the repo) and uses that
  checkout for its own repo, so a task worktree guards its own changes. The other repo still comes
  from `-Work`; `-RepoPath` overrides either.
- **Reading the guards:** each repo's own `agents\guards.txt`; blank lines and `#` comments are
  skipped, a line is `ID | repo | command` (a `|` inside the command is kept), and only the lines
  whose repo field matches run. Each line gets a per-file key - the first `BASE` line is `BASE-1`,
  the second `BASE-2` - so `-Only BASE-1` runs exactly one line and `-Only PC-03` runs every line
  with that ID.
- **Running:** from that repo's root, with `CARGO_TARGET_DIR=target/agent-guards`. A line with `&&`
  runs its parts in order and stops at the first non-zero exit code. `$ErrorActionPreference` is
  `Continue`, not `Stop`: cargo writes progress to stderr, and PowerShell 5.1 turns redirected
  stderr into a terminating error under `Stop`. The exit code is what decides pass or fail.
- **Output:** one row per line - ID, repo, command, PASS/FAIL, seconds - on screen and in
  `E:\CraftML\work\logs\guards-<yyyyMMdd-HHmm>.txt`, with a header naming the repos, the target dir
  and any `-Only` filter. A failing line prints the last 25 lines of its output. Exit code 1 if any
  line failed or a requested repo could not run its guards, 0 otherwise.
