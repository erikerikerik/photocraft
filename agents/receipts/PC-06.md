## Erik's five-minute check (the part of PC-06 that is yours)

Do this by hand in the app; the agent cannot sign off its own hands-on step. About five minutes.

1. **Start the manager.** In a terminal: `cd E:\CraftML\work\craft-ai-manager`, then
   `cargo run -p caim -- serve`. You should see it say it is listening on a `127.0.0.1` port and that it
   wrote the endpoint file. If LaMa is not installed yet: `cargo run -p caim -- models install lama --accept-note`
   once (about 200 MB, hashed while it arrives).
2. **Open the photo.** Start PhotoCraft (`cargo run -p photocraft`, or the built `photocraft.exe`) and open
   `E:\CraftML\work\.codex-tmp\pc06\golden.png` with File > Open. You should see the orange buoy on open
   water, 448x448, one "Background" layer.
3. **Select the object.** Drag a rectangle around the buoy, its black handle and its reflection with the
   marquee tool. You should see marching ants.
4. **Fill.** Edit > Generative Fill... You should see a "Generative Fill" dialog with a progress bar and the
   manager's own sentence ("Craft AI Manager is loading the LaMa model.", then "Craft AI Manager is running
   LaMa."), a percentage, and "Esc to cancel". About 9 s the first time, 2-3 s after that.
5. **Look at the result.** The buoy should be gone, the water should look like water, and the Layers panel
   should have a new "Generative Fill" layer above "Background". Click "Background": its pixels are untouched.
6. **Undo once.** Ctrl+Z. The buoy should be back and the "Generative Fill" layer should be gone - one step.
7. **Cancel one.** Start the fill again and press Esc (or click Cancel) about halfway. The dialog should
   close, the job should end as cancelled, and the document should be exactly as it was: no new layer, no
   half-filled rectangle.
8. **Close the manager.** Ctrl+C in its terminal, then Edit > Generative Fill... again. You should get one
   sentence, "Craft AI Manager isn't running", in a toast and in the status bar, and PhotoCraft should carry
   on working normally.

If any step looks different from that, say which one - that is the feedback Milestone 1 needs.

  receipt + screenshots until there is a CI job that can run a GUI. PC-05 covers the same path over MCP with a
  stand-in provider.
- **CI is paused on the photocraft fork** (HANDOFF, Oct 15): a maintainer has to re-enable Actions, so the
  checks on this PR may not run. The BF-02 row is in the same state.
- **Cancel granularity:** CAIM cancels between steps and interrupts socket work; a running ONNX session stops at
  its next cancellation boundary (CAIM README), so a cancel can land a second late.
