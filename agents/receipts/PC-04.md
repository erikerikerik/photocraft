## What landed

**Dependencies.** `photocraft-ai-client` is now a `[workspace.dependencies]` entry in the root `Cargo.toml` and is
referenced with `{ workspace = true }` by `apps/photocraft` and `apps/photocraft-cli`. It is **not** in
`apps/photocraft-web` and not in any L0-L6 crate: `cargo xtask layers` shows `photocraft-ai-client L6` with both
apps exempt, and `cargo xtask wasm` does not build it (the wasm set is L0-L5 plus `ui-egui`). `Cargo.lock` gains
two lines (the dependency on each app); no new third-party packages.

**Wiring.** One helper per app, so the line is not repeated:

- `apps/photocraft/src/main.rs`: `fn with_ai(mut session: Session) -> Session`, used at the one real session in the
  app (`PhotocraftApp::new(with_ai(Session::new()), services)`). Test sessions are untouched.
- `apps/photocraft-cli/src/lib.rs`: `fn with_ai(..)` plus `fn headless_with_ai(headless: Headless) -> Headless`,
  used by `info`, `run`, `batch`, `droplet`, `serve` and `mcp`. The `mcp` path builds its `Headless` itself and hands
  it to `PhotocraftMcp::with_backend(Backend::Headless(..))`, which is exactly what `headless_with_workspace` does,
  so `photocraft-automation` gains no dependency on the client.
- The client re-reads `endpoint.json` on every `submit` (PC-03), so a manager started after the app is picked up
  without restarting PhotoCraft.

**Provenance (B08).** `edit.generativeFill` now carries the `AiResult` provenance from the job's work step to its
apply step and returns `{layer, filled, window, ai: {model, device, provider, elapsedMs}}`. The engine passes the
provider's own words through unchanged. The command's params doc string was updated. The provenance is in the
background-job result too, so the control channel, `serve` and MCP see the same fields.

**CLI test (B04).** `apps/photocraft-cli/tests/cli.rs`:
`generative_fill_without_a_manager_says_the_manager_is_not_running` spawns the CLI with `CRAFT_AI_ENDPOINT` set
**only for the child process** to a path that does not exist, runs `select.rect` then `edit.generativeFill` on a
32x24 RGB document, and asserts exit code 1, no "panicked" in stderr, the last stderr line exactly
`error: `edit.generativeFill`: Craft AI Manager isn't running`, that `select.rect` printed a result and
`edit.generativeFill` printed none.
