## What was built

SPEC amendment 18's on-demand launch, with the B04/U11 wording. Nothing starts until the person presses a button, and nothing is claimed unless a process actually started.

- `crates/ai-client/src/app_file.rs` - reads `CraftAI/app.json` (version 1) from the manager's own data folder (`platform_data_dir`, the same folder CAIM writes to; not `endpoint.json`). Stat before open, one bounded read at 64 KiB, then an absolute path whose file name is `caim.exe` on Windows or `caim` elsewhere and which still exists. Missing, malformed, wrong-version, relative/empty/`.`, wrong-name, folder and over-cap registrations are ordinary errors, and every `RegistrationError` sentence names no path. `manager_state()` asks the installed client only when a launch could help, so `NotInstalled` / `NotRunning` / `ModelMissing` / `NoLaunchAction` come from what the machine actually says - never from the error text.
- `crates/ai-client/src/launch.rs` - starts that executable with one literal `open`, `Stdio::null()` for stdin/out/err and `CREATE_NO_WINDOW` on Windows. No shell, no command string, no PATH lookup, no install, no automatic launch. The registration is read again at click time; a removed executable is `NotRegistered`, a failed spawn is `Failed(<the platform's own words>)`. The child is reaped on its own thread, so the frame loop never waits on the manager.
- `crates/ui-egui/src/caim_ui.rs` - `needed_task()` decides from the command id and parameters (Generative Fill always; Select Subject and Remove Background only with `"method": "ai"`), `report_failure()` picks the sentence and at most one action, `open_pressed()` reports what the platform actually did. The engine's own missing-model sentence is kept where it already names the model.
- `crates/ui-egui/src/notices.rs` - a notice carries `Option<NoticeAction>`; `post_action()` is the only way to get one, `show()` draws the button, and pressing it calls `caim_ui::open_pressed`. `post()` still means "no action".
- `crates/ui-egui/src/lib.rs` and `crates/ui-egui/src/jobs_ui.rs` - both failure paths are covered: the immediate one in `run_command`, the background one in `JobsUi` (which records the AI task at `session.start` because `JobEvent` carries no parameters).
- `apps/photocraft/src/main.rs` - the two app-side seams (`caim_state`, `open_caim`) and the mapping between the two copies of the state enum. The web build and the CLI never install them, so they show no button and start nothing.
- 20 complete catalogs carry the six new strings (`Open Craft AI Manager`, the running / installed / starting / could-not-start sentences, and the retry line). The product name stays untranslated; `sr` uses Latin script.

No new dependencies. `crates/ai-client/src/endpoint.rs` changes one line only: `platform_data_dir` becomes `pub(crate)` so `app_file.rs` can use the same folder rule the manager already writes to. Endpoint authentication and the BF-04 permission checks are untouched, and the launch path never reads `endpoint.json`, so it can never log a token.

## Behaviour rules covered

- **Amendment 18 - nothing happens until the person asks.** `the_command_is_the_registered_executable_with_open` pins the program and the single `open` argument without starting anything; `nothing_registered_is_not_started` and `a_registration_whose_executable_went_away_is_not_started` prove the click-time re-read; `something_registered_that_cannot_be_started_reports_the_platform_words` proves a failed spawn is an error, not a success claim.
- **Amendment 18 - no usable registration means the installed sentence and no button.** `a_missing_registration_is_not_installed`, `a_malformed_registration_is_refused`, `another_version_is_refused`, `a_relative_or_empty_path_is_refused`, `an_executable_with_the_wrong_name_is_refused`, `a_deleted_executable_is_refused`, `a_folder_where_the_registration_belongs_is_unusable`, `a_registration_bigger_than_the_cap_is_not_read`; in the UI, `each_state_gives_its_own_sentence_and_action` and `no_seam_means_no_button_and_the_engine_sentence`.
- **Amendment 18 - the provider is asked only when a launch could help.** `nothing_registered_means_not_installed_and_no_question_to_the_manager` counts `tasks()` calls; `a_manager_that_offers_the_task_gets_no_launch_action`, `a_manager_without_the_task_is_reported_as_missing_a_model`, `a_registered_manager_that_never_answers_is_not_running`, `a_manager_that_answered_something_else_keeps_the_engines_own_sentence`.
- **Ordinary failures keep their own message.** `an_unrelated_failure_keeps_its_own_message`, `only_ai_commands_need_the_manager`; `the_action_is_visible_through_the_control_channel` keeps the state inspectable through the existing control protocol.
- **Paths with spaces and non-ASCII are ordinary.** `a_registration_path_may_contain_spaces_and_non_ascii`; `the_registration_sentences_name_no_path` checks no sentence leaks a path.

## Known gaps and follow-ups

- **No executable-bit check on Unix.** `read_registration` checks the name, that the path is absolute and that it is a file - not the mode bit. A registered `caim` without the execute bit therefore reaches `LaunchError::Failed` with the platform's words rather than the installed sentence. Deliberate: the name and existence checks are what amendment 18 names, and inventing a mode check would be a second policy.
- **The state enum exists twice.** `photocraft-ai-client` and `photocraft-ui-egui` are both layer 6 (`xtask/src/layers.rs`), so ui-egui cannot depend on ai-client; `caim_ui::CaimState` mirrors `app_file::ManagerState` and `apps/photocraft/src/main.rs` maps between them. A fourth variant added on one side will not compile the other way until the mapping is updated.
- **`RegistrationError`'s sentences are English-only.** They are diagnostic: `open_registered` discards them, and the UI works from the typed variants, so nothing unlocalized reaches a catalog.
- **The background path is stringly typed at the seam.** `JobOutcome::Failed(String)` carries no structure, so `JobsUi` records the AI task when the job starts (`ai_jobs`) and passes the engine's sentence through unchanged at failure. Re-plumbing `jobs.rs` was out of scope.
- **`needed_task` reads `params["method"]` directly** because `ai_segment_cmds::method()` is `pub(crate)`; the two places must agree if the parameter name ever changes.
- **FreeBSD** is required here (process launch, OS folders, client edits). Label and dispatch are recorded in the PR; `freebsd_ok.py` must PASS on the final head (x86_64 required, aarch64 advisory).
