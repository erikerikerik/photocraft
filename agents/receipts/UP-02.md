files. No `agents/` file, no receipt, no AI crate and no token is in any `upfix/*` branch.

What each fix does:

1. `chosen_type(filters, picked)` answers which file type gives the returned name its extensions: the
   one the portal reported, or, when it offered exactly one type, that one. The portal reports no pick
   then, and the dialog opens on the stem (`services::dialog_file_name`), so a bare `Swatches` came back
   bare. Several types with no pick still add nothing, and a typed extension stays the user's own
   because `with_chosen_type` keeps one it recognises.
2. `open_layer` now follows the layer trimmed size in scale mode (`resize_from_scale` + `write_size`)
   instead of leaving the document size `open` seeded into `width`/`height`; a remembered exact pixel
   size is left alone, because that is a size the user asked for. `open_layers` delegates to
   `open_layer`, so it is covered by the same fix.
3. `ENV_LAUNCH_OPTIONS` maps the six variables documented as the equivalent of a per-launch flag to
   that flag (`PHOTOCRAFT_PRESENT_MODE` -> `--present-mode`, plus frame latency, stroke trace, in-window
   menus and the two automation roots); `main.rs` extends `launch_options` with them, so an env-only
   launch keeps its own process. Empty and `0` mean off, matching the existing
   `PHOTOCRAFT_IN_WINDOW_MENUS` handling at `apps/photocraft/src/main.rs:265`. All six flags exist in
   the CLI parser.
