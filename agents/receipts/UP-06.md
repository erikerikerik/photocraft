**The bug** (`crates/ipp/src/tests.rs:189`, verbatim from `v0.10.0`): the last case of `error_statuses_and_broken_replies_are_errors` was

```rust
// Nobody listening.
let e = printers(&Endpoint::Tcp("127.0.0.1".into(), 1)).unwrap_err();
assert!(matches!(e, Error::Unreachable(_)), "{e}");
```

Port 1 is privileged, so it is usually closed on a CI box - but "usually" is not "never". On FreeBSD run 39171575189 (PC-09's head, the FB-02 row in `agents/TASKS.md`) something accepted the connection on port 1 and reset it, so the client got as far as sending and the case failed with `print server reply: sending: Broken pipe (os error 32)` instead of `Error::Unreachable`. The test was asserting a property of the machine, not of the client.

**The fix**: ask the OS for a free port and give it straight back.

```rust
let free = std::net::TcpListener::bind("127.0.0.1:0").unwrap();
let port = free.local_addr().unwrap().port();
drop(free);
let e = printers(&Endpoint::Tcp("127.0.0.1".into(), port)).unwrap_err();
```

The assertion is unchanged, and the `fake()` helper in the same file already picks its port this way, so the file is now consistent. A port the OS has just released is not guaranteed to stay free either, but nothing in the test holds it, and the window is the one the resolver and `connect_timeout` already sit in - unlike port 1, where a system service can be listening for the whole run.

## Why the old test was wrong, and the proof

There is no "red before" run here in the usual sense: the case passes on this PC with the old code, because port 1 happens to be closed here. That is the whole problem, so the proof went the other way - **what does a held port actually look like to this client**. In a scratch copy of the fork's crate (`.codex-tmp\ipp-standalone-06-fork`: the fork's `lib.rs` and `tests.rs` plus one throwaway test that binds a port, accepts once and closes), `printers()` on that port returned

```
HELD_PORT=61993 error=print server reply: sending: An established connection was aborted by the software in your host machine. (os error 10053) is_unreachable=false
```

`is_unreachable=false`, so the old `assert!(matches!(e, Error::Unreachable(_)))` fails on that machine - exactly the FreeBSD shape (`sending: Broken pipe (os error 32)`), a different OS error string for the same event. The scratch tree is still on disk under `E:\CraftML\work\.codex-tmp\` (untracked; deleting it needs an approval this agent does not have).

- With the change: **11 passed / 0 failed** on the fork branch (our `main` carries UP-04's two ipp tests; UP-05's test is not in this branch), and **9 / 0** on upstream's base in the standalone copy.
- The changed case ran **five times in a row on the fork and five times in the standalone tree: 10 of 10 green**, and it no longer depends on what is listening on a fixed port.
- The upstream commit message quotes the standalone numbers (9 / 0) because that is the tree the upstream gate ran on; the fork run is 11 / 0.
